Let's note CF-SR4：ファンとSecure Boot

対象Panasonic Let's note CF-SR4。確認したDMI product_nameは CFSR4-1。
症状と結果Live Linuxでのファン音を調査し、ファームウェアの静音モードを使う構成へ変更。カーネル6.12.113のイメージで、新しいMOK登録の案内後に利用者から静音改善の報告がありました。
確認の限界登録後のMOK・サービス・ACPI状態の出力は未回収。新しい6.12.115向けの構築・実機試験、長時間負荷、復帰後の挙動は未確認です。Let's note全シリーズへの対応を示すものではありません。

何を変更しているか

jubako USB版では、署名した acpi_call モジュールを介して対象機のファームウェアが持つファンモードを選びます。固定回転数やCPU電力制限は変更しません。実装はDMI名が CFSR4-1 と一致したときだけ動作し、稼働カーネルに対応したモジュールがなければ適用を停止します。ACPIの呼出し先を別機種へ流用するための手順はここでは提供しません。

状態の確認と、この起動中の復元

cat /sys/class/dmi/id/product_name
uname -r
mokutil --sb-state
systemctl status jubako-fan.service --no-pager
journalctl -b -u jubako-fan.service
sudo jubako-fan status

sudo jubako-fan status は対象機のACPI状態とCPU温度を読み取るために管理者権限を使います。ファンモードを変更する操作ではありません。

sudo systemctl stop jubako-fan.service

上の停止操作は、サービスが適用したファンモードをこのセッションの通常モードへ戻します。再度適用する場合は sudo systemctl start jubako-fan.service。サービスによる変更は起動ごとなので、停止した状態を次の起動へ保存する操作ではありません。温度・負荷・音の変化も合わせて記録してください。

MOKが必要になる理由

Secure Boot環境では、自分で構築したモジュールにも信頼できる署名が必要です。このUSB版は、構築側で保持する鍵でモジュールに署名し、対応する公開証明書をMOK（Machine Owner Key）として対象PCへ登録する方式です。登録は、その証明書で署名したモジュールを信頼する設定です。USBを挿すだけで自動登録はしません。

まず登録済みか確認します。公開証明書の出所と指紋も、構築者が提示した値と照合してください。

sudo mokutil --test-key /usr/share/jubako/hardware/fan-mok.der
openssl x509 -inform DER -in /usr/share/jubako/hardware/fan-mok.der -noout -subject -fingerprint -sha256

test-keyのsudoはMOK登録状態の確認用です。未登録で、この証明書を信頼して登録する場合だけ次を実行します。

sudo mokutil --import /usr/share/jubako/hardware/fan-mok.der

importのsudoはMOK登録要求を作るために使います。自分で一時パスワードを設定し、再起動時のMokManagerで証明書を確認して登録を承認します。この画面はLinuxへ入る前に表示されます。一時パスワードはLinuxのログインパスワードとは別です。登録後はtest-keyとサービス状態を再確認します。Secure Boot・BitLockerは有効のまま扱い、既存の鍵を消したり置き換えたりしません。

カーネルを更新するとき

カーネルが変われば、それに対応したモジュールの再構築が必要です。jubako USB版の構築処理では、採用カーネルごとに構築・署名し、版・ハッシュ・署名を検査します。同じ鍵の証明書が対象PCへ登録されたままなら、通常MOKの再登録は不要です。鍵を変更した場合や別PCでは登録状態を確認します。新カーネルでの実際のロードと冷却動作は別途実機で確認します。

秘密鍵は構築側だけで保管し、紛失に備えて非公開でバックアップします。USB・ISO・Git・このサイトへは収録しません。公開証明書だけでは新しいモジュールへ署名できません。
