検証と共有 — 自分のレシピを公開する

この作例の検証状況

ソース構文・XML・説明書リンク、Debian 13のAPT索引による依存解決シミュレーション、lb config の設定生成を確認しています。この公開レシピのフルISO構築・VM起動・実機起動は未確認です。ソース検査だけでは対象機器での動作確認を代替できません。

自分のPCで確認する

  • ISOが構築でき、チェックサムが一致すること。
  • 対象UEFIで起動し、Secure Bootの状態を確認できること。
  • GPU、画面、キーボード、日本語入力、Wi-Fi、音声が動くこと。
  • GUIの開始・終了とCUIへの復帰ができること。
  • RAMセッションで保存する作業を別媒体へ残せること。

使用したcommit、Debian版、PC/VMと結果を記録すると、変更後の差を比較できます。ソース検査だけでは実機の動作確認を代替できません。

自分の変更をGitで共有する

レシピと説明書をコミットし、生成物と個人データを含めないようにします。リポジトリの check-private.py はGitのステージ対象から典型的な秘密や生成物を探す補助で、内容の最終確認も必要です。

git add README.md LICENSE THIRD_PARTY.md .gitignore .github docs recipe scripts
python3 scripts/check-private.py
git diff --cached --check
git diff --cached

ISO・認証・秘密鍵・ログ・個人設定は公開対象から外します。Gitの作者メールも公開されるので、必要ならGitHubのnoreplyアドレスを設定してください。

説明書をGitHub Pagesで公開する

この説明書は docs/ の静的HTML/CSSです。自分のforkで公開する場合は、GitHubのSettings → Pagesで「Deploy from a branch」、ブランチと /docs を選びます。.nojekyll があるため外部のサイト生成ツールは不要です。

公開後は自分のURLで相対リンクを確認してください。元の説明書はこちらから読めます。

ライセンスと配布範囲

独自のコード・設定・説明はMITです。Debianパッケージの条件は別なので THIRD_PARTY.md と各パッケージのcopyrightを参照します。リポジトリにはISOやアプリバイナリを含めません。作成したISOを配布する場合は同梱物のライセンスを確認してください。

GitHub Actionsはソース検査のみを行います。ISOの自動構築・配布、USB操作は行いません。自動ログインとLiveユーザーのsudo利用を含む作例なので、共有端末のアクセス制御が必要な用途では別途設計してください。
