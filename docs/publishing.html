公開と確認範囲：最初のコミットからPagesへ

このdraftで確認するもの

  • shell構文、XML、パッケージ一覧、説明書のリンク。
  • build配下へ独立取得したDebian 13のAPT索引による依存シミュレーション。
  • lb configが空の作業先を準備できること。

フルISOの構築、VM起動、GPU/Wi-Fi/音声、日本語入力、Secure Boot実機起動はこの切り出した版で別途試す必要があります。元プロジェクトの確認済み機能をそのまま保証しません。

GitHub Pagesの設定

  1. README・recipe・scripts・docsのコミットをGitHubへpushします。
  2. repoのSettings → Pages → Build and deploymentでDeploy from a branchを選びます。
  3. ブランチmain、フォルダー/docsを選び保存します。
  4. 公開URLで相対リンクとスマホ表示を確認します。

docsは静的HTML/CSSで、.nojekyllを置いています。外部ビルドツールや公開用の認証情報を保存しません。公開予定のURLはhttps://cm3.github.io/jubako/で、現時点で公開済みという意味ではありません。

pushする前

git diff --cachedで対象を確認し、build・個人設定・認証・鍵・アプリバイナリ・私的調査記録が入っていないか確認します。このrepoは選んだ新しいソースだけから新規Git履歴を始めます。

ライセンス

独自の説明・設定・コードはMITです。Debianパッケージの条件は別で、THIRD_PARTY.mdと各パッケージのcopyrightを参照してください。repoはISOを公開しません。自分で作ったISOを配布するなら、同梱パッケージの条件を別途確認します。

自動チェック

GitHub Actionsはソース検査だけです。rootでLinuxを構築したり、USBへ書いたり、ISOをアップロードしたりしません。Pages公開はGitHub側の/docs設定で行います。

利用時の前提

自動ログインとLive userのsudoを使う個人作業向けの環境です。複数人で共有するPCのアクセス制御、全機器対応、保存領域の暗号化まで完成した製品ではありません。
