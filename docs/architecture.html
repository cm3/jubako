概要最初の構築変更する仕組み公開と確認範囲

仕組み：Linuxを組み立ててLiveにする

作る側と使う側

構築ホストのDebianでlive-buildを動かし、別のPC/VMでISOを起動します。WSLのネットワークやGPUの結果を、USBから起動したPCの結果と混同しません。

recipe → prepare → build/runs/…
       → debootstrap / APT / hook
       → kernel + initrd + SquashFS + EFI
       → ISO → VMまたはUSB起動

Liveの書き込みはRAMへ

圧縮された読み取り専用のOSと、起動中の書き込み層を組み合わせます。この例はnopersistenceなので通常の変更は再起動で消えます。OS本体の更新はレシピから再構築します。

Secure Bootの経路

live-buildへSecure Boot enableを指定し、署名済みDebianのshim・GRUB・kernelを使う構成です。設定が正しいことと、実際に対象のUEFIで起動できたことは別に確認します。独自kernel/moduleやMOK登録は初期範囲に含めません。

小さいGUI

labwcはWaylandの画面/ウィンドウ管理、Xwaylandは必要なX11アプリの互換経路です。端末はXfce Terminal。日本語入力はfcitx5がアプリとMozcをつなぎます。日本語を描画できるフォントと、ローマ字から変換する入力方式は別の部品です。

Gitへ置くもの

設計図のrecipe/scripts/docsだけを置きます。ISO、chroot、キャッシュ、ログはbuild内でGit対象外です。個人のhome、環境変数、認証を取り込む処理はありません。

版指定と再現性

Debian 13を選んでも、リポジトリ更新によりパッケージは変わります。版と一覧、構築ログを記録することは同一バイト列の保証ではありません。日付固定snapshotは必要に応じて将来追加する候補です。

Debian Live Manual、標準の構成管理を原典として参照できます。
