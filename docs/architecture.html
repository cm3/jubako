作例の概要構築する変更する仕組み検証と共有USB版の使い方

仕組み — レシピからLive環境へ

構築ホストでパッケージと設定を組み立て、別のPCやVMでISOを起動します。構築ホストのネットワークやGPUの動作と、USBから起動したOSの動作は別に確認します。

recipe → prepare → build/runs/…
       → debootstrap / APT / hooks
       → kernel + initrd + SquashFS + EFI
       → ISO → VM / USB

読み取り専用OSとRAM

OS本体を圧縮したSquashFSと、起動中の書き込み層を組み合わせます。この作例は nopersistence で動き、通常の変更は再起動で消えます。起動イメージを変更するにはレシピを再構築します。

署名済みの起動経路

live-buildで --uefi-secure-boot enable を指定し、Debianの署名済みshim・GRUB・kernelを利用する構成です。構築設定の検査に加え、対象UEFIでの起動を確認します。独自kernelや独自モジュールの署名管理は、この作例に含みません。

GUIと日本語入力

labwcがWaylandの画面とウィンドウを管理し、XwaylandがX11アプリとの互換を提供します。端末はXfce Terminal。fcitx5がアプリとMozcをつなぎ、Noto CJKフォントが日本語を表示します。文字を表示する機能と、ローマ字を変換する入力機能は別の部品です。

ソースと生成物

Gitで共有するものは recipe/・scripts/・docs/。ISO、chroot、キャッシュ、ログは build/ に作り、Gitから除外します。ホストのホームや認証情報を起動イメージへコピーする構成ではありません。

バージョンと再現性

Debian 13を指定してもAPTの更新によりパッケージは変わります。構築時のパッケージ一覧とログを保存すると差を追えますが、ISOが同じバイト列になる保証とは別です。日付固定が必要な用途では、Debian snapshotの利用を別途設計します。
