概要最初の構築変更する仕組み公開と確認範囲

最初の構築：レシピからUSB起動まで

1. ホストを用意する

Debian 13のamd64環境を使います。WSL2 Debianを想定しますが、実USBの起動機能はWSLだけでは検証できません。ホストへ構築ツールを導入するsudoと、後のUSBへの書き込みは別の作業です。

sudo apt update
sudo apt install live-build debootstrap xorriso squashfs-tools \
  dosfstools mtools syslinux-utils zstd python3 git

数GBのISOだけでなく、展開済みLinuxとキャッシュを作るので十分なディスク空きが必要です。まず20GB以上を目安に空きを確保し、実際の使用量を確認してください。ハードウェアや追加アプリにより変わる目安です。

2. 構築ソースを取得する

git clone https://github.com/cm3/jubako.git
cd jubako
bash scripts/check.sh
bash scripts/check.sh --dependencies

通常のcheckはshell・XML・説明書のリンク・設定条件を確認します。dependenciesはDebian 13の対象APT索引をbuild配下へ取得して、パッケージ解決を模擬します。ホストのAPT設定は変更しません。インストールやUSB操作は行いません。初回の索引取得にはネットワークが必要です。

3. 新しい作業先を作る

bash scripts/prepare.sh

recipeだけをbuild/runsへコピーし、lb configを実行します。ホームやワークスペース全体はコピーしません。prepareは通常userで行い、構築は次でsudoを使います。

4. ビルドする

sudo bash scripts/build.sh

sudoはchroot、ファイル所有権、一時マウントに必要です。成功時にISOの場所が表示されます。ログはrun内のlogs/build.log、チェックサムはSHA256SUMSです。

失敗したrunへ再びbuildしません。原因をレシピで修正してprepareし、新しいrunでbuildします。この初回作例は古いrunからの高速再利用や自動掃除を実装していません。

5. VMまたはUSBで起動する

ISOをVMの起動媒体に指定するか、Rufus等で自分のUSBへ書きます。USBを選ぶと既存データが消えるので、容量・モデル・退避を確認してください。repoはUSBを書き換えません。

署名起動の確認にはUEFI/Secure Boot対応のVMまたは実PCで起動する必要があります。通常BIOSのVMでGUIが出てもSecure Bootの成功にはなりません。Secure BootやBitLockerを無効化する手順は案内しません。

6. 起動後に試す

GUIは一度自動で開始します。Win+Enterで端末、デスクトップを右クリックでメニュー、Win+EscapeでGUI終了です。Firefox、Wi-Fi、日本語入力設定、音量設定はメニューから開きます。

最初は日本語入力のオン/オフ、変換、端末の貼付、Firefox、Wi-Fi接続を試し、PCと版を記録します。GUIが出ない場合はCUIからstart-desktop、ログは~/.cache/ja-live/desktop.logを確認します。

この例はRAMセッションです。アプリ設定・Wi-Fi・認証を再起動後へ残しません。残したい作業は別媒体へ明示保存してください。
