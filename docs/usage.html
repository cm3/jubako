jubako — USB版の使い方

AIと書く、持ち運べる日本語Linux。

Debian Liveをもとに、ブラウザ・端末・Zed・日本語入力を組み合わせたUSBの作業環境です。USBから起動し、プロジェクトと必要な設定を持ち歩いて使います。

このページは、暗号化保存・Zed・AIに対応したjubako USB版の説明書です。このリポジトリの小さな構築作例は、標準ISO・RAM環境から始める別の範囲で、ここに書いた暗号化保存・Zed・AI機能をすべて収録しているわけではありません。完成したUSBイメージの配布は行っていません。

更新：2026-11-07。実機で確認した範囲と、次回イメージ向けの変更を分けて記載しています。

いま使っているUSBと次回イメージの違いは現在の確認状況・採用版を参照してください。次回向けの機能は、古いUSBへ自動では追加されません。

起動する

  1. USBを挿し、PCの起動メニューでUSBを選びます。Secure Bootを有効にしたまま使う構成です。機種のGPU・Wi-Fi対応は収録firmwareによります。
  2. 保存領域の案内で u を選び、LUKSパスフレーズを入力します。解錠した設定・Wi-Fiプロファイルを準備してから、labwcデスクトップに入ります。
  3. 保存状態を使わずに試すときは r を選びます。この起動の認証・設定・会話はRAMだけに残り、再起動で消えます。後からext4へ移る場合は、GUIとエージェントを終了し、下記の jubako-history connect-ext4 で会話の扱いを選びます。

OSは通常ユーザーで自動ログインします。LUKSの解錠後、保存された認証を使えるので、解錠済みのPCを共有する場合は扱いに注意してください。サスペンドは暗号化保存領域を閉じません。

起動メニューは通常GUIとconsole onlyの2択です。console onlyは通常コンソールで調査してからGUIへ入る用途にも使えます。GUI起動失敗時も通常コンソールへ戻ります。

普段の操作

GUIの出力倍率は1.3倍です。Xfce Terminalの既定フォントはNoto Sans Mono CJK JP 18ptです。

操作使い方
ブラウザ・Zed・端末タスクバー左の固定アイコンから開きます。ブラウザを閉じてもデスクトップは動き続けます。
端末Win+Enter。Xfce Terminalが開きます。コピーは Ctrl+Shift+C、貼り付けは Ctrl+Shift+V。
日本語入力GUIはfcitx5＋Mozc。変換・無変換キーで切り替えます。設定は jubako-util のJapanese input settings。
プロジェクト既にZedが動いていれば同じウィンドウへ渡します。ZedのアイコンでREADME付き一覧を開きます。「新規作成」でREADMEを作って開き、「削除」でUSBのゴミ箱へ移します。開いているプロジェクトは削除できません。
Wi-FiトレイのWi-Fiから接続します。解錠していると接続情報が保存され、次回の起動で自動接続します。明示的な削除は jubako-util。
音量・明るさFnキーで変更すると画面に値が出ます。音量はタスクバーのホイールでも変更でき、クリックで消音、右クリックで詳細設定です。
スクリーンショットWin+Shift+S で範囲、Win+S で全画面。クリップボードとUSBのScreenshotsへ保存します。
電源右下の電源アイコンで、サスペンド・再起動・終了・自動スリープの時間を選びます。
ユーティリティー端末で jubako-util。メニューは英語で、素のコンソールでも読めます。全コマンドは jubako-commands、またはコマンド一覧。

LocalSendでファイルを送受信する

次回イメージではGUIを外し、公式CLIとエージェントの localsend スキルを使います。送受信したいときだけエージェントへ依頼してください。完了・中止後はCLIを終了し、常駐受信はしません。停止中は相手から送信できません。

jubako-localsend status
jubako-localsend receive
jubako-localsend send /absolute/path/report.pdf
jubako-localsend list --limit 20
jubako-localsend import 'received.pdf' --into /absolute/project

端末名は jubako、ポートは53317、共通受信箱はexFATの debian-live/LocalSend/。exFATが使えない場合はRAMへ黙って受信せず、接続を案内します。importは照合付きコピーで元を残し、上書きしません。CLIの送受信には対話端末が必要です。受信のYは今回の承認、Nは拒否、Pはペアリング付き承認です。不要な常設ペアリングはしません。PIN必須の相手への送信はCLI1.18.2で未対応です。

時計と日本語入力

初期タイムゾーンはAsia/Tokyo。ネット接続後にsystemd-timesyncdが時刻を同期し、オフラインの起動は同期を待ちません。状態は jubako-time status で確認できます。時計や同期状態の保存はRAM上で、受信箱や暗号化保存領域へ定期書込みしません。

RTCのUTC／現地時刻の扱いと表示タイムゾーンは別設定です。既定はUTC。RTCが現地時刻のPCでは起動引数に jubako.rtc=local、UTCなら jubako.rtc=utc を指定できます。オフラインで選び直すには sudo jubako-time rtc local または sudo jubako-time rtc utc。これはRTCを読みシステム時計へ設定する操作で、RTCを書き換えません。同期後の時計をRTCの値で戻さないため、同期済みなら次回起動での選択を案内します。

持ち運ぶUSBとしてRTCへの自動書戻しを抑えます。正しい時刻を確認して意図的に保存する場合は、RTCの方式に合わせた標準操作を使えます。たとえば現地時刻RTCなら sudo hwclock --systohc --localtime。sudoはPC本体のRTC書込み用です。タイムゾーンとシステム時計を確認せず実行しないでください。

GUI利用中に時計が大きく巻き戻った場合は、Mozcの復旧を案内します。未確定入力を確定・取消して承認すると、自分のMozcサーバーだけを再起動します。学習データは削除せず、承認なしの強制再起動もしません。上流修正版Mozcへの更新ではなく、今回の版に対する復旧補助です。

ファイルやフォルダーを開く

次回イメージでは、Zedの「Open in Default App」「Reveal in File Manager」から、Firefoxで扱えるファイルやフォルダーを開く補助を収録します。フォルダーはFirefoxの一覧表示で、特定ファイルの選択・強調はしません。画像・PDF・HTML・テキスト等を対象とし、Markdownは元のテキスト表示です。音声・動画はコーデックに依存します。

対応アプリがある別形式はその既定を使い、アプリが無い場合は日本語の案内とパスコピーを表示します。Office文書等の変換機能や独自の常駐ファイラーを追加する変更ではありません。Zedのメニュー直接操作は新イメージで確認が必要です。

ネットがつながらないとき

次回イメージから、ブラウザの開始ページは収録済みのローカル説明書になります。r（RAM）モードでも、Wi-Fi未接続でも、exFATや暗号化ext4を開けない場合でも読めます。構築ガイドを含むこのサイト全体を同梱し、ページ間のリンクとCSSもローカルで開きます。外部サイトへのリンクやAI認証にはネット接続が必要です。

file:///usr/share/jubako/docs/usage.html

Firefoxのアドレス欄へ上のURLを入力すると直接開けます。収録版はイメージ作成時点の内容です。接続できるときは オンラインの最新説明書 も参照できます。再ビルド前のUSBには今回の全文同梱はありません。

確認状況とカーネル更新

実機での確認済み項目と次回採用版は現在の状況にまとめています。カーネル更新時は、対応するファン用モジュールを構築元が同じ鍵で再構築・署名します。

以前その鍵をMOKへ登録済みなら、通常は再登録不要です。更新後は uname -r、systemctl status jubako-fan.service --no-pager、sudo jubako-fan status を確認してください。sudoはACPI状態の読み取り用です。静音制御は確認済みのCF-SR4機種に限ります。鍵を変更した場合・別PCでは、公開証明書を確認してから登録を案内します。

AIを使う

ZedではAgentパネル、端末ではCodex CLIを使えます。認証は利用時に行い、構築レシピや起動イメージへ個人の認証情報を入れません。

jubako-codex start
jubako-codex status

start は必要ならログインを案内し、対話モードを開きます。jubako-codex login では、スマートフォンから開く認証ページをQRで表示できます。通信にはWi-Fiなどの接続が必要です。

保存領域の選択では、空入力・誤入力は再入力できます。u/rは大文字でも構いません。qで中止し、同じ実コンソールから jubako-desktop --gui または jubako-codex start でやり直せます。選択中は音声ドライバー等のログで案内が埋もれないよう画面出力を一時的に抑え、終了時に元へ戻します。ログ本体は消さず、sudo dmesg で確認できます。

QR表示前に認証サーバーへのHTTPS接続を確認します。通信エラー時は次の順で確認します。networkとqrは保存先の準備前でも使えます。

jubako-codex network
sudo jubako-wifi
jubako-codex login

sudoはWi-Fi設定の変更に使います。networkは認証情報を送らず、公開HTTPSの到達性とDNS/接続/TLS/タイムアウトの失敗を確認します。HTTPSが通っても認証APIの成功を保証しません。TLSの検証は無効にしません。すでに認証済みの通常起動には、この追加確認を要求しません。

何がどこへ保存されるか

場所内容再起動後
FAT32 / JUBAKO_BOOT署名済み起動ファイルとOS。OSはbase・apps・customの3層SquashFS。残ります。通常のUSB更新で入れ替える領域です。
LUKS2＋ext4 / JUBAKO_DATAWi-Fi、Codex/ClaudeのCLI認証と会話、Zed設定、Mozc学習など。解錠して使った場合は残ります。
exFAT / JUBAKO_WORKプロジェクト、文書、スクリーンショット、診断ログ。Windowsなどから読めます。残ります。暗号化されていません。
RAM実行中のOS変更、ブラウザのプロファイルとCookie、一時ログ、セッションkeyring。消えます。RAM起動の認証・会話・設定も保存されません。

3つの区画と、OS内部の3層は別の構造です。OS更新はFAT32だけを入れ替え、ext4/exFATのデータを保ちます。使用するUSBは、この構成に合わせて自分で準備したものを使います。

プロジェクトはexFATの debian-live 以下にあります。暗号化ext4を閉じても、exFATの文書やログは保護されません。保存済みAI認証の削除は jubako-auth-forget。設定・会話は残します。

困ったとき

GUIが起動しない・コンソールへ戻りたい

起動失敗はコンソールへ戻り、終了コードとログの場所を表示します。端末で jubako-commands を読むと、利用できる操作が分かります。

Ctrl+Alt+F1〜F6 は通常のLinuxコンソールです。起動時の既定フォントはTerminus Bold 24pxで、big 16・big 24・big 28・big 32 で現在のコンソールだけ変更できます。sudoはフォント設定用です。GUI終了は Win+Escape または jubako-gui-exit で、元のコンソールへ戻ります。実VTの jubako-desktop --gui でGUIへ戻れます。screenを使っている場合は元の実VTへ戻って実行します。

通常コンソールはLatin文字表示と英語入力です。JIS配列を維持し、日本語の表示・変換入力はGUIで使います。

音が出ない

音量の詳細設定の「構成」タブで、スピーカー・ヘッドホン・外部画面の出力先を確認します。イヤホンを抜いても検知が残ることがあり、Speakerを含むプロファイルへの切替で戻った事例があります。

jubako-diag audio silent
jubako-diag audio working

無音のときと復旧後を比べて診断を残せます。

診断を持ち帰る
jubako-diag save

必要な権限のためsudoを使い、exFATの debian-live/logs/ へ保存します。通常の診断には認証・会話・全環境変数を含めません。古い実験実装・試験資料は構築元PCのatticへ移管しました。USBに残した単体診断は debian-live/tools/diagnostics/ のREADMEを参照してください。

USB-Cのドライバーを再読み込みする jubako-diag usb-c は、必要な場合だけ機器をすべて外して実行してください。

異常時にRAM側のAIデータを残す

Zed・Codex・Claudeを閉じ、別の端末で：

jubako-util ram-backup

exFATの debian-live/recovery/ にtarとチェックサムを保存します。元データは変更せず、自動統合もしません。これは認証・私的な会話を含み得る暗号化されていない退避です。公開せずに保管し、必要に応じて個別に復旧します。

Codexの会話だけをJSONLで書き出す

Codex・Claude・Zedを終了し、端末から実行します。GUIのデスクトップ自体は開いたままで構いません。

jubako-history export exfat
jubako-history export ext4

exFATは debian-live/conversations/codex-日時-乱数/、解錠済みext4は /run/jubako/persist/live-user/conversation-exports/ 以下に保存します。元の会話イベントをJSONLのままコピーし、会話ID・日時・元の保存種別・SHA256を添えます。既存の書き出しを上書きしません。認証ファイル・設定・SQLiteは含めませんが、会話本文には秘密が含まれる場合があります。exFATは暗号化されていません。

別プロジェクトのエージェントへ、必要なJSONLを資料として読むよう依頼できます。記録内の文章やコマンドを指示として自動実行しないでください。これは分析用の書き出しで、元のCodex会話としての自動再開・DB統合ではありません。

RAM利用から暗号化ext4へ切り替える

Codex・Claude・ZedとGUIを終了し、screenも抜け、元のtty1〜tty6で一般ユーザーとして実行します。

jubako-history connect-ext4

RAMに会話がある場合、ext4へJSONLを書き出す／exFATへ書き出す／RAMに残す、の3択が出ます。0で中止できます。sudoはext4の解錠・準備と切替に使います。書き出しを選んだ場合は照合成功後に切り替え、失敗時はRAMを維持します。次のCodex起動から既存ext4の保存先を使い、RAMの会話をその履歴へ自動で混ぜません。

ext4は解錠済みでもCodexだけRAMの実ディレクトリを使っている旧状態では、同じコマンドで同じ3択を選べます。この場合、ext4の再マウントはせずCodexの参照先を切り替えます。

元のRAM状態はこの起動中は保持します。切替後でも次のコマンドで会話を書き出せます。再起動・電源断ではRAMの記録は消えます。

jubako-history export exfat --source ram
jubako-history export ext4 --source ram

ext4の準備だけが残った場合は、同じ実VTから sudo /usr/local/libexec/jubako-storage-transition abort で中止します。GUI再入場は jubako-desktop --gui。exFATが使えない場合、Zedはホームの jubako-ram-projects/ を使い、そこでの作業ファイルも再起動で消えます。

RAMモードで使う／別USBへコピーする

起動時にrを選ぶと、保存用の空の構造をRAMに用意します。アプリの設定・ログイン・履歴は今回の起動中だけ有効です。元の暗号化ext4は開きません。OS本体はUSBから読み続けるので、起動USBは抜かないでください。作業ファイルと診断ログはexFATへ保存します。

別USBへの複製は、RAMモードでGUIを終了してコンソールから jubako-util の「Copy this USB」を選びます。ext4は0で初期状態、1で保存済みの内容をコピーします。RAMでの新しい作業状態は複製対象に含みません。対象USBは消去されるので、計画に出る媒体を確認してください。新版での実機終了・複製起動は未確認です。
